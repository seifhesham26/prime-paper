# Prime Paper Company - v2.0 Roadmap

The next major iteration (v2.0) of the Prime Paper Company management system introduces dynamic **Global Configurations**. This architectural shift will migrate hardcoded settings and environment-specific logic into a fully interactive, database-driven settings portal.

## Key Objectives
- Complete elimination of hardcoded business variables.
- Empower admins to independently configure localization, financial formatting, and system constraints.
- Secure configuration overrides based on RBAC (Role-Based Access Control).

## Proposed Architecture (Global Configurations)

### 1. Database Layer (`system_settings` table)
A new Drizzle schema will store key-value pairs representing global application state.
- `key` (String, Unique Primary Key)
- `value` (Text / JSONB)
- `metadata` (JSONB - for description, default value info)
- `updatedAt` (Timestamp)

### 2. tRPC Router (`systemSettings` domain)
New API routes will be implemented for accessing and modifying the table.
- `api.systemSettings.getAll` - Retrieves all global configurations.
- `api.systemSettings.update` - Safely updates specific config pairs.

### 3. Frontend Implementation
The existing `/settings` dashboard will be expanded with categorized sections or tabs:

#### A. Application Preferences
- Core localization defaults.
- UI theme enforcement (if applicable).

#### B. Financial Settings
- Configurable Currency Symbols (EGP, USD, etc.).
- Default Tax Rates or VAT percentages.

#### C. Operational Limits
- Maximum allowed unpaid balance per company before warning.
- Pagination limits for data tables.

## Execution Plan
1. Schema update: Add the new `.systemSettings` schema into `./src/db/schema.ts` and push the DB migration.
2. tRPC wiring: Integrate the new router into the root app router.
3. UI Development: Create an admin-only "System Configuration" client component to sit alongside the new User Settings panel.
